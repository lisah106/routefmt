# routefmt

Route tables written by hand or generated by different tools end up
inconsistent: some entries use `GET`, others `get`; some paths have
double slashes or a trailing slash; parameter placeholders show up
as `:id`, `{id}`, and `<id>` depending on who wrote that line last.
None of that matters to a router at runtime, but it makes diffs
noisy and makes it hard to tell by eye whether two routes actually
collide.

routefmt reads a list of routes, one per line, and prints each one
back in a single canonical form: uppercase method, single leading
slash, no trailing slash, no repeated slashes, and parameters
rewritten to `:name`.

## Input format

Each line is `[METHOD] /path/with/:params`. The method is optional
and defaults to `GET`. Blank lines and lines starting with `#` are
ignored.

```
get /Users/{id}/Posts//
POST   /users/:id/comments
/health
# internal, not exposed publicly
delete /users/<id>
```

Normalizes to:

```
GET /users/:id/posts
POST /users/:id/comments
GET /health
DELETE /users/:id
```

## Usage

From a file:

```sh
routefmt routes.txt
```

From multiple files, concatenated in order:

```sh
routefmt api-v1.txt api-v2.txt
```

From stdin, when there's no file to point at yet:

```sh
cat routes.txt | routefmt
```

Output goes to stdout. Lines that fail to normalize (an empty
parameter name like `{}`, or a parameter name with punctuation in
it) are reported on stderr with their line number, and the process
exits non-zero, but valid lines before and after are still printed.

Once a line normalizes, it's also checked against every route seen
so far. Two routes collide if they have the same method and the
same path shape once parameter names are ignored, since a router
can't tell `GET /users/:id` and `GET /users/:name` apart at request
time. A collision is reported on stderr, pointing at the first line
the shape appeared on, and the process exits non-zero, but both
routes are still printed to stdout.

To check a route table in CI without rewriting anything, use
`--check`. It runs the same normalization and collision checks but
never prints to stdout; any line that isn't already canonical, or
any collision, is reported on stderr and the process exits non-zero.
A clean, already-normalized table exits zero and prints nothing.

```sh
routefmt --check routes.txt
```

## Building

Standard library only, no dependencies:

```sh
cargo build --release
```

## What it doesn't do yet

It can't rewrite files in place; you have to redirect stdout
yourself. It also only understands one route per line, not route
tables embedded in a framework's own config format.
